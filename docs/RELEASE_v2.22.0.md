## 1. v2.22.0 完整更新日志（本次里程碑）

`v2.22.0` 是 Carlos Flow 从“**机械被动型门禁**”全面演进为“**智能全流程安全护栏外挂**”的里程碑版本，涵盖四大维度的深度升级：

### 🧭 智能向导与防误触体系 (Smart Guidance & Triage)
- **语义副作用分级识别 (`classifySideEffect`)**：
  - `LEVEL_0 (READ_ONLY)`：纯只读提问（分析、解释、为什么、看看、调研、对比）强制 0 分静默，不建卡、不卡死对话；
  - `LEVEL_1 (EPHEMERAL)`：临时调试与单测（加日志、打印、查状态）仅记录流水，不强加重门禁；
  - `LEVEL_2 (MUTATING)`：真实持久修改（重构、修复、修改、新增、删除）自动激活门禁守护。
- **会话多轮上下文消解 (`resolveContextScope`)**：
  - 用户在手机端或简短发言时发送“动手吧”、“按方案二改”等指令，系统自动在当前会话历史中回溯并提取真实代码文件路径，自动装配进任务卡 `scope`。
- **未决占位卡 5 分钟自动老化 (`checkPlaceholderExpiry`)**：
  - 误触开卡且 5 分钟内无真实派发（`dispatch_count=0`）时，自动静默撤销占位卡，会话无感恢复自由态。
- **一键人话撤销命令 (`flow_cancel`)**：
  - 用户随时发送“取消门禁” / “撤销任务”，系统 1 秒重置卡片状态并记录审计事件，瞬间解套。
- **100% 通俗大白话人话翻译 (`translateGateError`)**：
  - 彻底屏蔽内部技术黑话（如 SHA-256、Fail-Closed、锚点 veto），拦截时统一输出：`🛑 为什么停下 + 💡 为什么踩刹车 + 👉 怎么办`。

### 🧪 自动化工程质检 (Auto-Verify & QA Sheet)
- **Auto-Verify 测试命令自推断 (`detectProjectTestCommand`)**：
  - 自动识别 Node.js (`package.json` scripts)、Python (`pytest`)、Rust (`cargo test`)、Go (`go test`)，开卡未填 `verify.cmd` 时自动装配，消灭配置门槛。
- **完工电子质检交付单 (`generateQASheet`)**：
  - 任务落定 `PASS` 裁定时，纯内存生成 5 维度 Markdown 交付单（目标原话、修改范围、真实验证耗时与通过证据、双轴审查评语、开工前快照回滚指南）。

### ⚡ 存储瘦身与移动端体验 (Storage CAS & Mobile UI)
- **快照存储 CAS 哈希去重 (`snapshotFiles`)**：
  - 派发前快照全面接入 SHA-256 内容寻址指针去重，同一文件多次派发零额外体积开销，彻底解决快照体积膨胀问题。
- **移动端响应式折叠卡 (`settings.html` / `settings.js`)**：
  - 支持 `< 600px` 移动端视口自适应，长篇终端日志自动折叠收起；
  - 底部常驻 `[ 👉 复制下一步操作指引 ]` 与 `[ 🛑 遇到问题申请回滚 (恢复重来) ]` 大触控区，单手秒级交互。

### 🚀 进阶架构与生态扩展 (Proactive Guidelines & MCP Primitives)
- **事前代码规范注入 (`inferProactiveGuidelines`)**：
  - 派发执行者前，根据当前改动文件类型动态注入针对性的接口安全、并发锁、跨平台路径等最佳实践指南，从“事后挑刺”进阶为“事前引导一次写对”。
- **标准 MCP Resources / Prompts 官方原语扩展 (`src/mcp-stdio.mjs`)**：
  - 暴露标准只读资源（`carlos://state/current`、`carlos://rules/standards`）与开卡模板（`carlos-start-task`），大幅降低模型 Token 消耗。
- **本地错误自愈知识库 (`loadFailureMemory` / `saveFailureMemory`)**：
  - 自动持久化历史踩坑避坑经验，并在后续开发中自动注入提示，越用越聪明。
- **多 Agent 细粒度权限网格 (`validateAgentMesh`)**：
  - 任务卡全面支持 `agents` 专属 `allowed_scope` 划分，为团队化多 Agent 并发作业提供网格隔离。

## 3. 核心架构与用户体验的关键转变

### 转变一：从“死板监工”到“智能副驾”
- **以往**：哪怕用户只是问一句“这段代码为什么报错”，系统也会误判建卡，因为缺少 `scope` 将会话直接锁死。
- **现在**：底层内置语义副作用分类器，闲聊和只读分析**强制 0 分静默**；真要重构代码时，系统在后台**静默拍照备份并自动守护**，只在 AI 越界违规时才踩刹车。

### 转变二：从“技术黑话”到“老人家也能懂的大白话”
- **以往**：报错输出 `ERROR: scope 路径越界违背锚点约束`，非专业用户完全不知道发生了什么。
- **现在**：向导输出 `🛑 发现 AI 正在尝试修改没有约定过的文件。💡 为什么停下：AI 越界去动了其他代码。👉 怎么办：回复“允许追加”即可放行。`

### 转变三：从“繁琐手敲配置”到“全自动开箱即用”
- **以往**：开卡必须在手机或终端上手打 `verify: { cmd: "npm test" }` 以及一长串文件绝对路径。
- **现在**：用户说“按方案二改”，系统自动提取前文涉及的文件并校验磁盘真实性；测试命令由引擎自动扫描技术栈推断挂接。

## 4. 全工具链 22 个 MCP 操作完整映射表

Carlos Flow 内部 22 个核心操作划分为 **5 大类目**（Cindy 端通过两段式目录 `list_tools` / `call_tool` 调用，其他平台直接暴露）：

### 🛡️ 门禁主链 (gate · 4项)
1. `flow_submit_requirement`：提交任务卡留痕（支持 Auto-Verify 自推断与 Agent Mesh 网格）。
2. `flow_claim`：领取派发名额（自动注入事前代码规范与历史避坑经验）。
3. `flow_dispatch`：派发子 Agent 执行（自动执行文件 CAS 去重快照）。
4. `flow_verdict`：记录审计裁定（PASS / DIRECTION / LOCAL，自动生成电子质检单）。

### 🧪 真实验证与负对照 (verify · 3项)
5. `flow_run_verify`：真实 spawn 执行验证命令并捕获退出码与输出指纹。
6. `flow_falsify`：执行负对照实验（验证改动前失败 + 改动后通过，证明测试具备判别力）。
7. `flow_check_scope`：运行时 Git Diff 越界自查（对比基线判定是否有未授权改动）。

### 🔍 独立审计与取证 (audit · 4项)
8. `flow_audit_axes`：派发 Standards 规范轴与 Spec 验收轴独立审查。
9. `flow_audit_submit`：提交独立审查员的双轴裁决结论与证据。
10. `flow_audit_guard`：独立核验双轴证据齐全度与合法性。
11. `flow_audit`：读取 SHA-256 跨天链式审计流水（防篡改可追溯）。

### ⚙️ 运维·状态·还原·解套 (infra · 10项)
12. `flow_status`：查询当前门禁完整状态与向导阶段看板。
13. `flow_stats`：查询存储占用、去重率、会话健康度与归档建议。
14. `flow_protocol`：读取机器可读的完整协议规范。
15. `flow_mode`：切换 pro（专业）/ guide（向导人话）模式。
16. `flow_bypass`：显式授权开启/关闭单次免检通道。
17. `flow_cancel`：**【v2.18新增】** 一键撤销任务卡，重置状态回自由态。
18. `flow_add_user_msg`：写入用户原话流水作为锚点数据源。
19. `flow_save_result`：持久化保存 Agent 执行结果与输出摘要。
20. `flow_revert_plan`：基于快照生成原子还原计划（支持“恢复重来”一键还原）。
21. `flow_diff_hunks`：Git diff hunk 级变动分析。

### 🧭 智能触发 (trigger · 1项)
22. `flow_trigger_check`：语义副作用分级、意图评分与自动开卡决策引擎。

## 5. 常见问题与应急回滚指引

### 常见操作指令
- **我想直接退出门禁自由聊天**：对 AI 回复 **“取消门禁”**，系统一秒清空任务卡恢复自由态。
- **代码改乱了，我想回到开工前**：对 AI 回复 **“恢复重来”**，系统按快照 100% 逐字节保真还原。
- **我想给当前任务增加一个允许改动的文件**：对 AI 回复 **“允许追加 src/xxx.js”**，系统自动扩展白名单并补拍快照。

### 版本回滚预案
如果生产环境需要降级到特定历史版本，可通过 npm 直接安装：
```bash
# 回滚到前序稳定版
npm install -g carlos-flow@2.18.1

# 重新初始化当前平台配置
carlos-flow init --target <cindy|opencode|cursor|vscode|cline>
```
状态目录 `~/.carlos-flow` 采用向后兼容设计，版本降级或升级均无需手动清理数据。
