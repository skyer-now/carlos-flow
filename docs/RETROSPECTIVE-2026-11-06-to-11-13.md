## 三、做得好的地方

### 3.1 【最重要】把"承诺"逐条变成机器门禁 —— 本轮最高价值的方法论

第三方审查（`docs/AUDIT_REVIEW.md`）报告 11 项指控、10 项属实。修完之后**没有停在文档里**，而是把每条承诺固化成自动门禁：

| 承诺 / 缺陷 | 固化成什么门禁 |
| :--- | :--- |
| README 宣称的每个能力都要有代码路径 | `npm run check:claims`（10 条核心承诺 + 6 条关键不变量） |
| `inputSchema` 每个参数都要被真实读取 | `npm run check:params`（抓"算出却从未使用"的死变量） |
| 同一 schema 不得重复注册 handler | `npm run check:no-dead-handler` |
| 越界改动必须真被阻断 | `npm run test:scope`（真实 git 仓库，5 用例） |
| 审计链必须真能发现篡改 | `npm run test:audit`（真实篡改记录，23 用例） |
| Bridge 身份不能串 | `npm run test:bridge`（端口上是别人的 bridge 时不复用，6 用例） |
| 提交信息与注释必须中文 | `npm run check:lang` + `npm run test:lang`（自检防假绿） |
| 发布闸方向必须正确 | `npm run test:gate`（10 条锁 semver 方向） |
| Bridge 转发通路必须真通 | `check-all.sh`（真 RPC 往返，断言 19 个工具） |

**这条思路在 11-13 又被复用了一次**：黑窗事故后没有只修代码，而是加了 CI 的 bridge 矩阵 job（ubuntu + windows 双跑）。**「每出一次事故，先问『怎么让机器下次自动抓住』，再问『怎么改代码』」——这是这 8 天沉淀下来的最核心的经验。**

### 3.2 发现并命名了"静态一致性 vs 行为兑现"这个元问题

审查报告里最有价值的一条不是某个具体 bug，而是：**现有门禁擅长查静态一致性，不擅长查行为兑现**——所有 P0/P1 问题一个都没被现有门禁抓到。正因为识别出了这个元问题，后续才有 `check:claims`/`check:params`/`check:no-dead-handler` 三个新门禁族，以及 11-13 的真 RPC 冒烟。**这是方法论级别的收获，不是修 bug 级别的。**

### 3.3 测试从"源码目录"走进"真实安装路径"

`test/package-e2e.mjs`（v2.6.3）走完整链路：`npm pack` → 装到**干净临时目录** → 从 `node_modules` 拉起 MCP server → 真实 JSON-RPC 握手 → 校验 23 个关键文件齐备 / bin 有 shebang / ghost.json 工具清单与服务端逐一对齐。

**关键收益**：v2.6.2 修掉的两个严重 bug（插件找不到单包 → 自动触发静默失效；ghost.json 缺 3 个工具 → Cindy 用户根本看不到）**只有走真实安装路径才会暴露**，源码目录测试永远发现不了。

### 3.4 承诺降级为准确表述，而不是硬撑

T-80 审计链宣称"防篡改"，实测裸 SHA-256 能被洗白。修复没有继续吹，而是**分模式如实告知**：设 `CARLOS_FLOW_AUDIT_KEY` → HMAC-SHA256（篡改必被发现）；未设 → 降级 `plain` 并在 `verifyAuditChain()` 结果里显式标注 `mode` 字段，README/SECURITY 同步改成准确表述。

同时修了 `audit()` 的跨天链断裂（午夜后任意历史天的篡改今天查不出，等于完美洗白）。**"误报比漏报更伤信任"这条判断体现在 legacy 分支只计入计数、保持 `prev` 不变上。**

### 3.5 阻断点选在语义正确的位置

T-79「越界直接阻断派发」的修复，选点不是"派发前"而是**"裁定前 + 基线增量"**：
- 派发那刻子 Agent 还没动手，它之后改哪些文件无从得知；此时跑 git diff 得到的是用户自己已有的未提交改动，拿去拦会**误伤正常用法**。
- 正确语义是"本次执行有没有越界"，所以用"当前改动 − 派发前基线"判定，既拦得住又不误伤。

**这是设计判断上的亮点，不是修 bug 层面的。**

### 3.6 清理"用户看得见但测试不红"的那一类问题

`4b7d33c` 的对外产物全面排查首轮报出 **49 项**——个人私有路径随包分发（3 个 P0）、插件找不到单包、ghost.json 工具清单缺 3 个、验证脚本检测的是**一个不存在的包**、审计 grep 模式必然检出自己导致这项审计从来没通过过……

**这一类问题不会让任何测试变红，但会直接被用户看到。** 主动建 `scripts/full-audit.mjs` 做独立体检并归零，是这轮里投入产出比最高的一次。

### 3.7 跨平台问题的诚实修复

- `5171983`：验证命令不再硬编码 `cmd.exe`——Linux/macOS 上命令根本没跑、exitCode=127、**门禁形同失守**

## 四、教训（按严重度排序）

### 🔴 L1 · 承诺与实现脱节，且现有门禁**一个都抓不到**

**事实**：11-07 第三方审查 11 项指控、10 项属实，全部 P0/P1：

| # | 承诺 | 实际 |
| :--- | :--- | :--- |
| T-79 | "越界 → 运行时 git diff 对比白名单，直接阻断派发" | `enforceScope` 是纯函数、**从不自己跑 git diff**，完全信任调用方传入；`flow_dispatch` 里**零 scope 校验**——**承诺完全不成立** |
| T-80 | "改一条全链断裂 / 防篡改" | 裸 SHA-256 无密钥，**实测能洗白** |
| T-83 | `flow_audit` 的 `date` 参数可按日期过滤 | **完全失效**（算出却不用），传 `date=2020-01-01` 读到的是今天 |
| T-88 | 审计链防篡改 | `prevHash` 只取当天 tail，**跨天链断开**，午夜后任意历史天篡改查不出 |

**根因**：门禁只覆盖"文件在不在、版本对不对"这类**静态一致性**，对"宣称的行为是否真的发生"无能为力。

**代价**：项目对外的核心承诺有一整段时间是不成立的，而所有检查全绿。

**机制**：`check:claims` / `check:params` / `check:no-dead-handler` + `test:scope` / `test:audit` / `test:bridge` / `test:package`。

### 🔴 L2 · 对话语言合规 ≠ 产物语言合规

**事实**：11-07 同一会话里**对话回复全部是中文**，但连续 **6 个 git 提交信息**写成完整英文段落（`fix(release): v2.6.1 — add missing shebang to bin entry` 等）。用户指为"非常严重的技术事故"。

**为什么隐蔽**：事发时对话语言完全合规，肉眼扫"回复"看不出任何问题。漏检的全部是**产物**——而产物会**持久化并对外分发**（提交信息进 GitHub、文档进 npm 包），影响面比一次对话大得多。

**三个深层根因**：
1. 记忆写成了原则、没有可核对清单 → 执行时靠临场判断就漂移
2. 产物从不被单独扫 → 提交信息、注释、文档天然被忽略
3. **守门脚本本身在 Windows 上是假绿**：JS 正则的 `.` **不匹配 `\r`**，Windows 文件是 CRLF 行尾，"按 `\n` 拆分"后每行残留 `\r`，导致 `(.+)$` 完全匹配不上、**一行都扫不到**——表现为"本地全绿、CI 才报出真问题"

**机制**：`scripts/lang-audit.mjs` + `test/lang-audit.test.mjs`（12 项自检防假绿），并写明"凡是行级扫描脚本都要用 `split(/\r?\n/)` 并写一条 CRLF 回归用例"。

### 🔴 L3 · 本地绿 ≠ CI 绿

**事实**（11-08）：`test/bridge-identity.mjs` 造假的仓库根目录在系统临时目录下，Node 从那里向上找不到仓库的 `node_modules`，`@modelcontextprotocol/sdk` 解析失败 → MCP server 起不来 → bridge 不响应 → 客户端挂死 60s（`status=null`、无输出）。

**根因（关键）**：**本地能过是环境巧合**——开发机用户目录下恰好有一份 `node_modules` 被向上回溯命中。测试的正确性依赖了它声称要隔离的那件事。

**同窗口同类**：`13dc942`、`99bd293` 连修两次；审计链测试用 `toISOString()`（UTC 日期）与 `state.js` 的本地日期不一致，UTC+8 的 00:00–08:00 会读写到另一天的文件。

**机制**：假根目录必须带上 `node_modules`（Windows 用 junction、POSIX 用目录软链，失败退化为复制）；日期统一用本地日期。

**这条与 L2 的 CRLF 问题合起来看**：**Windows 特有的假绿有两类——CRLF 让行级扫描静默失效、环境巧合让隔离测试自动通过。**

### 🔴 L6 · 沿用既有代码而没读懂语义

**根因**：这段代码是仓库里既有的（11-13 09:13 `03f01d8` 引入），我**沿用了它的结构而没读懂它的语义**，且全仓没有任何测试覆盖这个方向。

**机制**：`scripts/publish-gate.mjs` 纯函数 + `test/publish-gate.test.mjs` 10 条断言锁方向。

### 🟠 L8 · Windows 提交丢失可执行位

`core.fileMode` 不跟踪 exec bit，`check-all.sh` 以 `100644` 进仓库，Ubuntu runner 直接 `126 Permission denied`，而 Windows runner 却通过——**平台间的假象**。

**机制**：CI 用 `bash ./check-all.sh`（不依赖 exec bit）+ `git update-index --chmod=+x`。

## 五、可复用经验（后续开发直接套用）

### 5.1 施工四步法
```
1. 取基线   git checkout <good-ref> -- <file>      不凭记忆重写整个文件
2. 定点改   edit（精确 oldText 替换）              不整体覆盖
3. 静态验   node --check + git diff --stat         确认只动了预期的行
4. 行为验   真 RPC 往返 / 真断言                   不看日志、不看"启动了"
```

### 5.2 结论的证据分级
| 结论强度 | 需要的证据 | 可以说的话 |
| :--- | :--- | :--- |
| 未验证 | 无 | 「已修改，**未验证**」 |
| 静态确认 | 语法检查 / diff 审查 | 「代码已就位，**未跑通**」 |
| 行为确认 | 真 RPC 往返、断言输出 | 「已验证：拿到 19 个工具」 |
| 环境确认 | 截图 / 窗口句柄 / 进程表 | 「已验证：无可见控制台窗口」 |

**禁止**：用「已验证」描述只有前两级的证据。

### 5.3 承诺 → 门禁 的转化路径
任何对外宣称的能力，落库前先问一句：**"如果这条明天失效，哪个机器会红？"** 没有答案就补一个门禁；补不了就**降级为准确表述**，别硬撑。

### 5.4 测试必须走真实路径
源码目录里绿的测试不算数。至少要有：**真实 git 仓库**（scope/audit）、**真实安装路径**（npm pack → 干净目录 → 真实握手）、**真实篡改**、**真实跨进程**。

### 5.5 识别三类假绿
1. **静态门禁查不出行为兑现** → 补 `check:claims` / `check:params` / 真实验证
2. **对话合规不等于产物合规** → 产物单独扫 + CRLF 回归用例
3. **本地绿不等于 CI 绿** → 隔离测试要显式补齐被隔离掉的环境（node_modules / 时区 / 行尾）

### 5.6 单一真源
版本号 → `package.json`；发布判定 → `scripts/publish-gate.mjs`；工具清单 → `ghost.json` 与 `src/index.js` 对齐检查。**任何"同一个值出现在多处"的地方，都要有一个真源 + 一条同步脚本。**

### 5.7 发布纪律
- 改版本号后必跑 `npm run sync:version`
- 推 tag 前先 `git tag -l` 确认不重名
- 推 `v*` tag **等于**发 npm（不是两件事）
- 发布后必回 registry 交叉验证（CDN 有延迟，加 `?t=<随机>` 或查 `/carlos-flow/<version>`）
- 推 tag 前本地跑 `./check-all.sh`

### 5.8 交互纪律
- 有真实决策点才提问，**一次只问一个具体问题**，先给推荐答案与默认动作
- 用户不回复 → 按推荐方案直接做，不停在等待态
- 已问过并已回答的，**绝不复读**
- 全程简体中文，**产物**（提交信息/注释/文档/CLI 文案）同样中文
- 不引用或复述"规则/技能"的措辞
